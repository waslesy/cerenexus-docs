# 第 8 章:API 命名——为什么模型名字这么长

## 8.1 C 端 vs API 端:同一个模型,两张脸

你用过 ChatGPT、DeepSeek 的网页版或 App——那里选模型很简单。

| 选项 | 说明 |
| :--- | :--- |
| 🚀 快速模式 | 直接出答案,快 |
| 🧠 思考模式 | 多想一会儿,准 |

点一下,完事。底层是什么模型、多少参数、哪个版本——你不需要知道,也不给你看。

**输入 API 端完全不同。**

打开 API 文档,模型列表长这样:

```
qwen3-235b-a22b-2507
deepseek-v4-pro
claude-sonnet-4-20250514
gemini-2.5-pro-preview-05-06
gpt-5.1
```

没有"快速模式"和"思考模式"的按钮。所有信息都**直接写在名字里**。

| | C 端 | API 端 |
| :--- | :--- | :--- |
| **选择方式** | 快速模式 / 思考模式,两个按钮 | 模型名直接带 thinking 或 instruct |
| **参数细节** | 不显示 | 全标在名字上 |
| **控制粒度** | 一个开关 | 你想快选 flash / mini;你想准选 pro / thinking |

> **C 端替你藏起来的复杂度,API 端全部还给你。**

API 端没有"快速模式"按钮——所有控制在你自己手里。

## 8.2 拆一个名字看看

拿这个为例:

> **qwen3-235b-a22b-2507**

一段一段拆:

| 片段 | 含义 | 翻译成人话 |
| :--- | :--- | :--- |
| **qwen3** | 模型名 + 代际 | 千问第三代,MoE 架构 |
| **235b** | 总参数量 | 总共 2350 亿参数。B = Billion = 10 亿 |
| **a22b** | 激活参数量 | 实际每次推理激活 220 亿参数。A = Activated |
| **2507** | 发布日期 | 2025 年 7 月发布的版本 |

**总参数 vs 激活参数是什么?**

有些模型采用 MoE(混合专家)架构——相当于一个团队里有八个专家,但每次来一个问题,只有两三个专家被叫醒干活。总参数是八个人加起来的总和(235B),激活参数是每次实际干活的人数(22B)。

> MoE 的好处:脑子大,但每次只用一小部分,算得快、成本低。

## 8.3 命名字段速查

API 命名**没有统一标准**。但常见的字段就这几类:

| 字段类型 | 常见写法 | 含义 |
| :--- | :--- | :--- |
| **模型名 + 代际** | qwen3, gpt-5, claude-4, deepseek-v4 | 哪个系列、第几代 |
| **总参数** | 235b, 70b, 8b | 总共多少个参数,数字越大模型越大 |
| **激活参数** | a22b, a3b | MoE 架构每次实际激活的参数 |
| **发布日期** | 2507, 20250514, preview-05-06 | 什么时候发布的版本 |
| **思考标识** | thinking, instruct, base | thinking = 开启深度思考;instruct = 经过指令微调,能正常对话;base = 基座模型,只会接龙,一般人用不到 |
| **上下文长度** | 1m, 128k | M = 百万 token,K = 千 token |
| **后缀(旗舰/轻量)** | pro, flash, mini | 同系列里的大中小杯,见第 3 章 |

> **思考强度不在这张表里。** low / medium / high / max 是你调 API 时单独设置的参数,不是写在模型名里的——第 11 章会详细讲怎么调。

## 8.4 实战:看到名字别慌

看到一个陌生的模型名,按这个顺序拆:

### 示例一

```
deepseek-v4-pro
↓
deepseek → 深度求索
v4       → 第四代主力
pro      → 旗舰款,最强
```

### 示例二

```
gemini-2.5-flash-1m
↓
gemini → Google 的模型
2.5    → 第二代第五版
flash  → 速度优先款,能力打折但快
1m     → 100 万 token 上下文窗口
```

### 示例三

```
qwen3-30b-a3b-instruct-2509
↓
qwen3    → 千问第三代
30b      → 总参数 300 亿
a3b      → 激活参数 30 亿
instruct → 经过指令微调,能正常理解你说的话
2509     → 2025 年 9 月发布
```

不需要背。就像你不需要背每个人的身份证号——见多了自然认脸。用 API 选模型时对着上面的速查表拆一遍,三五次之后就闭眼能读了。

**名字再长,也就是这几个零件拼的。**

## 本章要点

| 概念 | 一句话 |
| :--- | :--- |
| **C 端 vs API 端** | C 端替你藏复杂度,API 端全还给你 |
| **命名元素** | 模型名、代际、参数规模、激活参数、发布时间、思考标识、上下文 |
| **MoE** | 总参数大,激活参数小——脑子大但每次只用一部分 |
| **instruct vs base** | instruct 能正常对话,base 只会接龙,一般人用不到 |
| **思考强度** | 不在模型名里,是调 API 时单独设的参数 |
| **没有标准** | 不同厂商命名风格不同,但零件就那几类,拆开看就行 |
